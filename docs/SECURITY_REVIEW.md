## 行为调整

| 配置 / 操作 | 当前行为 |
| --- | --- |
| 观察模式 | 频次、细分规则及地区策略记录“本应拦截”并放行；暂停已有自动封禁的执行，不新增内核限速。人工地址黑名单与人工封禁继续执行 |
| 关闭自动封禁 | 所有自动策略均不新增持久封禁记录。地区 / 直接拦截仍拒绝当次连接，频次阈值仅记录；独立限速仍执行。已有封禁按原有效期处理 |
| 自定义端口封禁 | 内核拦截选定端口；插件同时拒绝该 IP 的 frp 登录，即使登录端口不在所选范围中 |
| 地址白名单 | 从更宽黑网段中精确扣除白名单，不放行同网段其他地址，也不跳过系统防火墙 |
| 临时名单到期 | 插件匹配立即检查时间；后台每秒检查到期并安排合并同步，内核生效时间取决于同步完成时间 |
| 手动解封 / 封禁到期 | 持久状态成功更新后才移除内存状态；按整个封禁前缀重置窗口和令牌桶，避免解封后沿用旧计数 |
| 切换后端 | 新后端成功同步后清理旧受管规则，再替换管理器引用；失败保留原引用并尝试恢复保护，恢复失败明确报错 |
| 请求重新同步 | 接口返回“已安排同步”，实际成功与失败查看同步状态 |
| 改密码 / 登出 / 重新初始化 | 撤销旧会话并持久保存。单管理员面板登出撤销全部会话；重启不会恢复被撤销的 token |
| CSV 导出 | 使用认证头下载，不接受 URL query token |

观察模式与系统 dry-run 是不同配置：dry-run 预览网络规则、不写内核；观察模式用于校准自动策略。
关闭观察模式后，仍未到期的自动封禁恢复执行。

## DeepSeek 清单逐项处理

| 编号 | 核实结论 | 修复 |
| --- | --- | --- |
| 1. nft 读失败后建默认链 | 存在；“另一条 accept 链让后续 base chain 不执行”的解释不正确。真正风险是失败后盲目创建 / 更新系统同名链 | 读取与 JSON 解析返回错误并中止；只有可靠确认无 input 链时才用排他创建在独立 `inet frpfirewall` 表建链，绝不重写既有 policy |
| 2. 同步并发、驱动引用竞态 | 存在 | 同步、预览、替换与切换共用管理器事务锁；驱动操作另有串行锁，引用在锁内读取；普通接口请求经合并队列同步 |
| 3. 缺少 iptables 静默成功 | 存在于内核下发；插件拒绝连接仍可工作 | 工厂检查能力；只启用具备对应 restore 命令的协议栈，空栈返回错误 |
| 4. 伪造头绕过登录限制 | 存在 | 禁用默认可信代理，以实际 TCP 对端限制登录；等待认证锁后再次检查预算，防止并发请求提前通过检查 |
| 5. 请求体无上限 | 存在 | 原生 HTTP 限制普通请求 1MiB、名单导入 8MiB、属地上传完整请求 201MiB；含已知长度及分块输入，超限返回 413 |
| 6. 检查与封禁插入非原子 | 存在，属于逻辑竞态 | 封禁、手动封禁、解封与到期处理共用生命周期锁，覆盖查重、落库及内存修改；解封同目标的历史重复活跃行，来源删除也解除全部对应历史行 |
| 7. /24 解封不重置来源窗口 | 存在 | 按前缀包含关系清理真实来源 IP 的窗口与桶，保留相邻网段计数 |
| 8. 切换不清旧后端 | 存在 | 增加只清理本项目规则、子链与集合的能力，切换失败保留旧引用并执行故障恢复 |
| 9. 按地址解封吞落库错误 | 存在 | 先更新数据库，失败返回错误并保留内存封禁；不再报告假成功 |
| 10. 属地安装共用临时文件 | 存在并发写入风险；原先下载互斥不能保护上传 | 上传 / 下载安装共用锁，唯一临时文件、校验、文件同步、替换与热加载串行完成；失败移除临时文件 |
| 11. 页码乘法溢出 | 存在，需管理权限，Recovery 原会返回 500 | 限制页码到安全乘法范围，切片偏移不产生负值 |
| 12. 时长乘法溢出 | 存在，需管理权限配置极端值 | 所有写入口严格解析与限制秒数，历史值转换饱和计算。0 仍表示永久，正数不因溢出变永久 |
| 13. events hours 溢出 | 存在，影响查询范围 | 与同类查询统一限制至 720 小时；非法 / 超限值使用默认范围 |
| 14. 属地 HTTP 超时冲突 | 存在于慢传输，不是尺寸达到某值就必然失败 | 在原生响应写入器上单独延长属地请求读写截止时间至 13 分钟；前端匹配，下载源总预算仍为 12 分钟 |
| 15. 白名单不能排除黑 CIDR 单 IP | 存在 | 前缀差集生成内核目标，覆盖单 IP、CIDR、IPv6、自动封禁及端口分组；重叠集合按地址族规范化去重 |

## 最初审查及附加提示

重叠问题已经在上表列出，以下补充其余修复：

| 问题 | 修复结果 |
| --- | --- |
| 临时黑白名单只在刷新时判断有效期 | 地址与地区匹配检查当前时间；保留运行态有效期，每秒到期检查安排内核同步 |
| 驱动警告隔离后前端可能看不到 | 能力说明包含驱动自身警告，并明确 nft 限速的 IPv4 边界 |
| iptables 先清空再逐条追加，失败丢防护 | 批量 restore 预检与每协议栈原子提交；跨栈失败恢复旧受管快照；整次同步使用总截止时间，不再每地址创建一个进程 |
| 改密码 / 退出不撤销 JWT | 持久会话版本验证；限制算法、签发者与必需到期字段，改密、登出及初始化更新版本 |
| 4096 的窗口上限使允许配置的高阈值不可达 | 与接口统一到 100000；窗口保留时间覆盖全局和细分规则配置，长窗口不被固定 30 分钟裁掉 |
| 超速分支提前返回，无法达到封禁阈值 | 所有尝试先计数并完成阈值判断，再执行独立限速 |
| 观察模式仍拒绝阈值连接 | 按已确认范围记录并放行自动策略，事件页增加“策略观察”分类 |
| multiport 每个区间错误计 1 个名额 | 单端口占 1、区间占 2，按 15 个名额分片；黑名单和限速均使用同一逻辑 |
| 细分与全局内核限速叠加 | iptables 匹配后的 RETURN 跳过后续本项目限速；nft 普通限速子链使用同样选择语义，退出后继续系统规则 |
| 救援顺序错误、遗漏端口链、失败退出 0 | 摘入口，清空所有受管链后删除；清理 nft 限速子链和集合；临时文件唯一，失败退出非零，预览不修改规则 |
| 用户名错误跳过 bcrypt | 无论用户名是否匹配，都执行密码校验 |
| 登录限流 map 无限增长 | 最大 10000 个来源、定期淘汰；满额时拒绝新增来源，封锁期间不继续增长失败数组 |
| 无读取用途的 droppedEvents 并发增长 | 移除无锁计数写入 |
| URL 接受 token | 移除 fallback，前端导出改为认证头与 Blob 下载 |
| iptables Restore 从快照选择程序并吞错误 | 只接受固定程序与受管链、限定跳转目标，预检全部快照后批量恢复，错误返回；nft 文本快照只供检查，拒绝重放系统规则 |
| 插件 healthz 无回环校验 | 增加实际来源校验；仍要求插件监听回环地址 |
| tmp 下不同 Go 包冲突 | 原缺陷复现源改为 `.go.txt`，普通构建不扫描；正式回归放在各自包中 |

## 当前边界

- iptables 的 IPv4 与 IPv6 分别原子提交，跨协议栈用恢复处理，不能称为整机单事务。
- nft 当前 IPv6 内核限速仍不支持，会报告能力边界；IPv6 黑名单支持。
- 自动健康检查发现误封后回滚尚未实现；同步恢复失败必须根据错误状态处理或执行救援。
- 反向代理后登录限流按代理对端计数，各访客共享该限制；未新增可信代理配置入口。
- 请求体限制约束单请求，窗口计数按来源保存；未把本轮修复扩大为全站连接数或总内存配额系统。
- 属地安装并发验证覆盖安装串行与失败清理；未在业务主机替换实际属地数据库或执行大文件生产下载。
- 上述测试覆盖已确认问题及主要异常路径，不等于保证不存在其他漏洞。
