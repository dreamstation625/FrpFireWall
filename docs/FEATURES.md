## 观察模式与自动封禁

| 开关 | 自动策略 | 人工地址黑名单 / 人工封禁 |
| --- | --- | --- |
| 观察模式开启 | 频次、细分规则和地区策略记录「本应拦截」并放行；暂停已有自动封禁的执行，限速也放行 | 继续生效 |
| 自动封禁关闭 | 不新增持久封禁记录；地区 / 直接拦截仍拒绝当次连接，频次阈值只记录；独立限速仍生效 | 继续生效 |

关闭观察模式后，仍未到期的原有自动封禁会恢复执行。系统设置中的 dry-run 用于预览网络规则，
不会写入内核；它与策略观察模式的配置入口不同。

地址白名单可以从更宽的黑名单网段中精确排除单个 IP；名单到期后插件立即按时间判断，
内核更新由每秒到期检查触发并合并同步。白名单不授予绕过系统防火墙的权限。

频控在应用层统计插件回调里的连接尝试，支持 IPv4 / IPv6，独立于防火墙的内核限速模块。
旧版受管内核限速在全量同步时清理，已有封禁仍按原范围执行。

## 频控细分规则

**频控策略** 页分两张卡：上面是**细分规则**（可有多条、按顺序匹配），下面是**全局规则**（兜底）。

匹配顺序是从上到下，**第一条命中的规则取代全局规则** —— 窗口、阈值、阶梯、限速全部换成
那条规则的。一条都没命中才走全局规则。**名单不受影响**：白名单、地址黑名单、地区黑名单
（含地区条目）都排在细分规则之前判定，命中就轮不到规则了。

一条规则的条件可以是（同一维度内多选是「或」，不同维度之间是「且」）：

| 条件 | 写法 | 落点 |
| --- | --- | --- |
| 国家 / 地区 | 下拉多选 ISO 码（也可直接输入） | 应用层 |
| 省份 | 下拉多选（中国省级行政区） | 应用层 |
| 城市 | 下拉多选 + 可直接输入（中国城市为主） | 应用层 |
| 来源 IP / 网段 | `1.2.3.4, 203.0.113.0/24` | 应用层 |
| 代理（隧道）名 | 下拉选最近出现过的，或直接敲名字 | 应用层 |
| 目的端口 | 多个端口或区间；Login 按 `bindPort`，TCP 新连接按学习的固定 `remotePort` | 应用层 |

**代理（隧道）名是可选条件**，用来给不同代理定不同力度：填了就只对那个代理生效，留空表示不限代理，仍按地区、来源等其他条件匹配。留空的规则也可匹配登录尝试，同一来源在不同代理上的连接按同一条规则累计；所有匹配条件都留空时，请使用全局规则。
不同代理要不同参数就建多条规则、把专用的排前面（按顺序匹配，先命中的生效）。下拉里的候选
来自事件日志里**最近出现过**的代理名，所以新建的隧道、以及被事件保留期清掉的旧隧道都不在
里面 —— 那些直接敲名字回车即可，填错了的表现是永远不命中（和城市那一栏一样）。

⚠️ **登录阶段没有代理名**：frps 只在建立连接（`NewUserConn`）时才报隧道名，登录（`Login`）
那一刻还不知道要连哪个代理。所以带代理条件的规则在登录时不参与匹配 —— 这是那一刻没有这个
信息，不是规则没生效。代理名可以与目的端口、地区、来源 IP 一起填写，填写的各项必须同时匹配。

**所有细分规则统一在应用层匹配和计数。** 填写端口不再切换到内核，也不会清空阈值与地区条件。端口和代理名均可选：都填时取「且」，只填一项时按该项筛选，再与其他条件共同匹配。

- 端口表示**实际被访问的目的端口**，不是访问者的来源端口，也不是封禁范围。
- 登录回调按配置的 `bindPort` 匹配；TCP 新连接通过同一用户、会话和代理名的端口映射匹配。未知端口跳过端口规则并继续其它规则或全局兜底，映射状态在 **frp 接入 → 代理端口映射** 查看。
- 带端口规则的窗口与令牌桶按**规则 + 目的端口 + 来源 IP**分别计数；不带端口规则仍按规则与来源 IP 计数。
- 自动封禁仍使用全局封禁粒度，范围固定**全端口**。人工黑名单仍可选择全端口、仅 frp 端口或自定义端口。
- 统计的是**登录尝试和新连接**，不是 HTTP 请求数。普通 HTTP、UDP 等没有 `NewUserConn` 回调的访问不纳入此类连接计数；HTTPS / tcpmux 等有回调的代理按代理名匹配，不能将客户端来源端口当成目的端口。

### 代理端口自动学习

无需 frps Dashboard。将插件 `ops` 更新为 `["Login", "NewProxy", "CloseProxy", "NewUserConn"]`，然后让 frpc 重新连接，学习代理的固定监听端口。**更新 frps 配置通常需要重启 frps，会中断隧道，请避开业务高峰操作。** 若有其他修改代理配置的插件，应将 FrpFireWall 排在最后。

- 目前支持 **TCP + 固定 `remotePort`**，不支持随机分配端口、负载均衡组，以及 HTTP / HTTPS / tcpmux 等共享端口的推断。没有 `NewUserConn` 回调的访问仍无法计数。
- `NewProxy` 在实际监听之前调用：「已申报」只表示收到注册请求；同一会话出现新连接后显示「已收到连接」。注册失败可能留下申报记录，因此这里不是在线代理列表。
- 映射按用户、runID 和代理名隔离；关闭代理后删除对应会话记录，旧 runID 的关闭不会删除不同 runID 的映射。同一会话申报冲突时将端口标为未知，避免错误匹配。同一 runID 重建代理遇到延迟关闭回调时，可能需要等待关闭完成后重新注册。
- 映射仅在内存中保存，**本程序重启后需让 frpc 重新连接学习**。最多保留 4096 条，达到上限会记录告警，新代理端口保持未知。
- 未知端口不会猜测，带端口条件的规则不命中；不带端口的规则、全局频控和已有黑名单仍照常判定。

例如「国家：巴西、中国香港 + 端口：25666 + 直接拦截」只在来源属地和已学习的端口同时匹配时触发；再填代理名时，该名称也必须匹配。触发后的自动封禁依然是来源 IP 的全端口封禁，端口不是封禁范围。

**动作有三种，按填了什么推出来：**

| 动作 | 怎么配 | 效果 |
| --- | --- | --- |
| 限速 | 填 `per_sec`（+ `burst`） | 按来源 IP 限速，超出的连接回调被拒绝；不生成内核限速规则 |
| 频次封禁 | 填窗口 + 阈值（+ 阶梯） | 超阈值就把该 IP 封进内核，阶梯升级 |
| 直接拦截 | 打开「直接拦截」开关 | **不等频次**，命中条件就拒绝这次连接，自动封禁开启时还会把该 IP 封进内核（全端口、按阶梯时长） |

「直接拦截」与「限速 / 封禁」互斥，保存时会报错 —— 命中就拒的规则根本走不到计数那一步，
两条配在同一条里只会有一条生效，不如直接不允许。代理名、端口、地区和来源条件可以组合匹配。
命中之后同样按「命中即封禁」把该 IP 落进内核（全端口、按阶梯时长），所以第一次之后的
连接是被「封禁中」挡住的；在 **封禁记录** 里能看到这条封禁的来源指向那条规则。

限速与窗口封禁可以同时开启：每次尝试先计入窗口，达到阈值就封禁；尚未达到阈值再判断令牌桶。
这样即使访问频率超过每秒速率，被拒绝的尝试也能累计触发封禁。保存规则不会预先把整段 IP 或端口写入内核。
规则删除、停用或更改匹配条件时，由它产生的封禁通过来源引用解除；人工解封会重置相关端口的窗口和令牌桶。

省份取值已经做了归一化：界面里给的是「广东」，属地库返回「广东省」也照样命中。
所以从 **IP 属地** 页复制过来的省份名可以直接粘进规则里。属地查不到时按不命中处理
（不会因为查不到就变成"命中所有人"）。

城市的写法与省份不同 —— **三种地区条件的校验强度是刻意不一样的**：

| 条件 | 校验强度 | 写错会怎样 |
| --- | --- | --- |
| 省份 | 必须是 34 个中国省级行政区之一 | **保存时报错** |
| 国家 / 地区 | 只校验两位字母的格式，不查真实性 | 不会报错，只永远不命中 |
| 城市 | 只做归一化，不查真实性（候选表非封闭） | 不会报错，只永远不命中 |

省份能查是候选集封闭（34 个），国家码不能查是因为"能查的只有属地库那份常见来源地表"，
拿它当白名单会把哈萨克斯坦、古巴这类真实国家一起拒掉；城市候选集本身开放，查不了。
所以国家与城市这两行的下拉都允许**直接输入后回车**（`allow-create`），
不这样写就只能在导入文件里配出来。城市名建议从 **IP 属地** 页复制，避免写错而不自知。

规则改动和全局策略一起保存（后端在同一次事务里落盘）。规则表上方如果出现红框，
说明有规则编译不过 —— 那种规则**不会生效**，红框里会给出具体原因。

## 按地区拦截（国家 / 省份 / 城市）

黑白名单的每条条目都有一个**目标类型**：地址（默认）或地区。选地区之后输入框换成下拉，
**一条可以填多个值**（多选用下拉，国家与城市也可以直接输入后回车）：

| 类型 | 填什么 | 例子 |
| --- | --- | --- |
| 国家 / 地区 | ISO 两位国家码 | `CN`、`HK`、`US` |
| 省份 | 中国省级行政区 | `广东`、`福建` |
| 城市 | 城市名（中国城市为主） | `深圳`、`Brisbane` |

**地区条目不预先写任何内核规则。** 属地库只能「给 IP 问地区」，反查不出某个国家的 IP 段
列表，所以内核层无从匹配。实际做法是：某个 IP 连上来 → 查出属地 → 落在地区条目里 →
把这**一个 IP** 封进内核（全端口、**封到条目到期为止**）。也就是「命中即封**该 IP**」，
而不是「预先封住整个地区」。没被命中过的地址在内核里没有痕迹，对方换个 IP 去扫别的端口
就挡不住 —— 真要挡整段，用人工 CIDR 黑名单条目并选择封禁范围。

**列表里显示中文名，库里与导出的仍是国家码。** `HK,JP,SG` 在界面上是
「中国香港、日本、新加坡」（鼠标悬停能看到原始的匹配值），搜索框里**中文名和国家码都能搜**。
中文只存在于展示层 —— 后端另给一个 `target_label` 字段专供显示，匹配、归一化、
导出文件里始终是国家码。所以导出文件可以直接拿去别处用，界面上看到的「中国香港」
不会写进文件（真写进去的话，那份文件再也导不回来）。

容易踩的几条：

- **粒度互斥**：一个条目只能是一种类型，没有"某国的某个省"这种写法。要同时封国家和省份
  就建两条。
- **校验强度**：省份必须是 34 个中国省级行政区之一（写错直接报错）；国家码只校验两位字母
  的格式；城市只归一化、**不查真实性** —— 国家与城市**写错不报错，只永远不命中**。
  所以这两类的下拉都允许直接输入，输入后回车即生效。
- **属地查不到时算不命中**，不是"命中所有"。属地库没加载时地区条目一条都不会生效，
  而不是把所有连接一起拒掉。
- **白名单地区是「豁免封禁」**，语义与地址类白名单一致：命中就不封，不代表放行端口。
- **地区条目没有范围与端口**：命中即封固定按全端口走，编辑时这一整块不显示。
- **条目上的「有效期」同时是「命中之后封多久」**：命中即封，封到条目到期为止；选「永久」
  就是封永久。它**不走全局的频次封禁阶梯** —— 那套阶梯会按该地址自己的封禁历史升级，
  同一个条目能封出 10 分钟和 1 小时两种时长，条目上那个有效期反倒完全不参与。
  地址条目没有这一层含义（它靠常驻内核规则，条目在就封着）。
  一个边界：封禁时长在**命中那一刻**定死，之后把条目的有效期改短，已经封进去的 IP
  不会跟着缩短。
- **编辑条目时「有效期」下拉留空 = 保持原有效期**；选具体档位才是"从现在起重新计时"，
  选「永久」才是"改成永久"。这个契约在后端落成**字段缺席 = 不改动**，
  所以"进来改个备注"绝不会顺手动到有效期。已经过期的条目在列表里带 `已过期` 标记，
  不动有效期就仍然是过期、不生效。列表里不展示"剩余 xx 时间"，有效期就是封多久。

**条目可以停用**：列表上的「启用/禁用」开关直接切换。停用的条目不参与判定、
不产生内核规则（与"不在名单里"等价），但保留在名单里、随时可以再启用。

**解禁是联动的**，不需要手工两边跑：

- **删掉名单条目** → 被它拉黑的地址一起解禁，响应里报出解禁条数。
- **停用名单条目** → 同删除待遇：由它封掉的地址一起解禁。
- **停用 / 删掉 / 改掉细分规则** → 由它封掉的地址一起解禁。规则侧用的是「匹配条件的
  **内容签名**」而不是规则 ID（规则表是整表替换、ID 每次都变），所以改个备注不会误伤，
  改条件才等于换了一条规则。
- **在封禁记录页解封某个地址**时反过来清依据：它是因为某条名单条目被封的，那条条目
  一起删掉；是因为某条规则被封的，规则不动（条件型的规则没法"移除一个地址"，
  强行动作只会把整条规则改坏），只留一条事件提示你去调规则。
  被解封的地址如果是靠**网段**条目封的，条目也留着 —— 删掉它等于顺手放行另外 255 个地址，
  那超出了点这一次解封的授权范围。

导入导出文件里，地区条目带**类型前缀**，多值用**分号**（逗号是列分隔符）：

```
country:CN;HK,all,测试来源     # 导出的形态：地址列带前缀，范围列恒有一列
province:广东;福建,all
city:深圳,all
1.2.3.4,frp,扫描源             # 地址条目照旧，没有前缀
```

导入时范围列与备注列都可以省 —— 地区条目上的范围会被忽略（它固定全端口），
写 `custom:...` 也不生效：

```
country:CN;HK
province:广东;福建
city:深圳
```

无前缀的一律按 IP / CIDR 解析，所以老版本导出的文件不用改一个字节就能导入。

## 黑名单的封禁范围

黑名单每条条目单独设置封禁范围，在 **黑白名单 → 黑名单** 页的「范围」列可以看到，
新增 / 编辑时选择，批量导入时可指定该批的默认范围：

| 范围 | 实际效果 | 什么时候用 |
| --- | --- | --- |
| `all`（默认） | 该地址访问**本机全部端口**的入站包一律丢弃，含 SSH、面板 | 确认是纯攻击源，不怕误伤；或被扫得受不了想彻底断掉 |
| `frp` | 只丢弃 frp 服务端口（bindPort + 代理端口，TCP 与 UDP 都包含）上的入站 | 只想挡掉对方对 frp 的访问，还要让本机其它服务保持可达 |
| `custom` | 只丢弃手动指定端口上的 TCP / UDP 入站包，支持区间 | 需要保护具体服务端口，保留其它端口可达 |

> [!NOTE]
> 范围只影响内核层。插件回调拿不到目的端口，因此 `all` / `frp` / `custom` 在插件侧都会拒绝该地址的 frp 连接。
> **自动封禁固定使用 `all`**，不跟随手动条目的端口范围。

`frp` 范围涉及的端口集合 = **bindPort + 代理端口**。代理端口可在 **frp 接入 → 受保护端口** 编辑，
支持区间写法，直接照抄 frps 的 `allowPorts` 即可：

```
80,443                        # 逐个列举
20000-30000                   # 整个区间，落库就是这一行，不会展开成 10001 条规则
80,443,20000-30000,7000-7100  # 混着写，逗号 / 分号 / 空格分隔都认
```

区间是**原样下发**给内核的（iptables 写 `--dports 20000:30000`，nft 写 `dport { 20000-30000 }`），
所以封一个大区间和封一个端口，规则条数一样。改动代理端口后**保存立即生效，无需重启**，
`bindPort` 在此处只读。系统设置页的代理端口字段同样支持即时生效。

选择 `all` 之前请确认这个地址不会同时是你的运维入口 —— 全端口封禁会把 SSH 一起挡掉，
届时只能用 `scripts/frpfirewall-panic.sh` 或带外控制台来救。

导入文件里第二列是 `all` / `frp` / `custom:端口` 时才被当作范围，否则整体按备注处理，
所以老版本导出的两列文件（`地址,备注`）可以直接导入：

```
1.2.3.4,frp,扫描源        # 只封 frp 端口，备注"扫描源"
203.0.113.9,custom:8080;9000-9100,扫描源  # 多个端口用分号分隔，避免与列分隔符冲突
1.2.3.0/24,办公网          # 范围取该批默认值，备注"办公网"
1.2.3.5                   # 范围取该批默认值
```

**白名单没有范围**（恒为 `all`）：它描述的是「豁免谁的封禁」，本身不产生封禁动作，
所以界面上不显示这一列，接口传了也会被忽略。

自定义范围必须提供有效端口；新建、编辑或手动封禁请求缺少端口时会被拒绝。
地区黑名单条目不提供范围选择，命中后封禁具体 IP，时长跟随该条目有效期。

## 服务器出口 IP

**设置** 页有一块「服务器出口 IP」，**概览** 页每次进入会自动探一次：

- 探测方式是问第三方回显服务「你看到的我是谁」（`myip.ipip.net` → `api.cip.cc` →
  `myip.fireflysoft.net` → `api.ipify.org` → `ifconfig.me`，按序取第一个成功的）。
  不走"查本机路由表会用哪个源地址"那条路：多出口、策略路由、机器在 NAT 后面时
  它会给出一个完全不是公网出口的地址，而且**看不出来它错了**。
- **探测会向第三方暴露服务器 IP**，所以收敛了三处：结果缓存 60 秒；设置页只在点
  「检测」时才探测（打开页面不自动探）；概览页进页面探一次，靠缓存挡住重复请求。
- 探到的地址**不在白名单里时会弹窗提示加入**（弹窗里的地址可以改成手填的实际地址，
  也可以点「暂不」—— 记的是这个地址本身，换了出口 IP 会重新问一次）。
  值得加的理由：回源流量、本机对外访问一旦被自己的规则拦掉，表现是"服务莫名连不上"。
- 自动探测不到时（机器压根没有公网地址、回显服务全不通）在设置页直接填实际公网
  地址，一样能加进白名单。

## 防火墙拦截统计

**概览** 与 **防火墙** 页都有「防火墙拦截统计」（概览里是精简版，同一个组件），
显示内核实际丢掉了多少包，和事件日志是两套东西：

| | 记的是 | 在哪看 |
| --- | --- | --- |
| 防火墙拦截统计 | 内核丢掉的**包**（不区分连接） | 概览 / 防火墙 → 防火墙拦截统计 |
| 事件日志 | frp 登录阶段被本程序**拒绝的连接** | 事件日志（`login_blocked`） |

被封的地址在 SSH 上撞过来只能进防火墙拦截统计（不经过 frps）；登录口令试错被拒只进
事件日志（包根本没走到内核过滤那一步）。两边不重叠，也别把两个数字加起来。

几点必须知道的口径：

- **数是内核数的**，不是本程序数的。程序只下发规则。
- **规则一重建就归零**：全量同步、切换后端、重启防火墙服务都会让数字从 0 重新开始。
  所以它是「自上次重建以来的累计值」，不是历史总量。
- **每 5 分钟采一次样**用于画趋势，采样点保留 7 天。趋势图画的是「这一批新增多少」，
  不是累计值（累计值重建后会掉回 0，画成折线会出现毫无意义的断崖）。
- **粒度看后端**：iptables 每个地址一条规则，能数到单个地址；nftables 把地址装进
  集合、规则只有一条，只能数到分组（全端口那一组 / 某个端口组）。
  这是两种后端的结构差异，不是开关。

## 事件日志记了什么

每条事件带 **时间 / 类别 / IP / 属地 / 账号 / 代理 / 详情 / 操作者**，筛选支持类别、
时间范围与关键词（关键词会同时匹配 IP、账号、**代理名**、属地与详情）。保留期默认
30 天，在系统设置里可改。

**「代理」列只在访问连接类事件上有值。** frps 只在 `NewUserConn` 回调里带代理名
（连哪个隧道是这一刻才确定的），`Login` 回调没有，所以登录类事件这一列是空的 ——
这是客观数据，不是漏记。

## GeoIP 数据库（可选）

不放也能跑，只是属地显示与国家封禁不可用。三个库各自独立加载，缺哪个都不影响
其它库可用：

| 文件 | 面板下载源 | 作用 |
| --- | --- | --- |
| `GeoLite2-Country.mmdb` | `P3TERX/GeoLite.mmdb` 的 release | 国家封禁的基础，做地域拦截必须有；也是国家 / 大洲的权威来源 |
| `GeoLite2-City.mmdb` | 同上 | 中国大陆与港澳台之外的省 / 市主要靠它（约 64MB；**不含运营商**） |
| `ip2region.xdb` | `lionsoul2014/ip2region` 的 `ip2region_v4.xdb` | 中国大陆与港澳台的省市主要靠它（中文名、精度更高），不依赖 MaxMind 账号；运营商只有它能给 |

### 一键下载更新

面板 **IP 属地** 页每个库下面都有「下载更新」按钮，直接从上面的源拉最新版，
不用手动下载再上传。按钮旁边标着**预估大小**（如「约 64MB」，点下去之前对耗时有个数），
以及一个「前往下载源仓库」链接 —— 想先去看看上游更新了什么、或手动取文件都方便。
几个要点：

- **走加速源**。这些都托管在 GitHub 上，国内直连基本不可达，所以下载支持选择公共
  加速源（ghfast.top / gh-proxy.com / ghproxy.net / gh.llkk.cc），默认是「自动选择」——
  依次尝试、直连排在最后兜底，某个源挂了会自动换下一个。
- 下载完**先校验文件头再替换**，校验不过旧库原样在用。把一个下到一半的坏文件换上去，
  属地功能会整个失效，比安装失败严重得多。
- 同一时刻只允许一个下载任务，避免重复传输与资源竞争。已经在下的时候再点
  会直接提示，而不是排队等一个 64MB 的文件。
- 加速源是公共代理，随时可能挂。列表由后端内置并实测维护，**不接受自定义前缀**：
  让调用方随便传一段前缀等于开放任意 URL 转发，面板能连到的内网地址会被逐个探测。
- 全部源都失败时，错误里会列出每个源各自的原因。只回一句「下载失败」没法指导下一步。

也可以自己把文件放进数据目录（自动加载），或者在面板 **IP 属地** 页上传本地文件 ——
上传路径与下载走同一套「写唯一临时文件 → 校验文件头 → 原子替换 → 热加载」，
安装阶段共用互斥锁，写入完成后同步文件；上传与下载不会交错覆盖同一个目标。
单文件上限 200MiB，属地上传与同步下载允许 13 分钟传输，下载源总预算为 12 分钟。
反向代理自身的请求体与超时限制也需要匹配。

### 同时装了多个库时的合并顺序

- **国家 / 大洲以 MaxMind 为准**：Country 库优先，Country 库没查到时由 City 库补，
  两个都没查到时按 xdb 记录里的 ISO 国家码兜底。
- **省 / 市的取值来源按国家分流**，不是"哪个库为主"：
  - 中国大陆与港澳台 → **先取 ip2region**（返回中文省市名，精度高于 MaxMind；后者在
    国内经常只到省、甚至给错城市）
  - 其余地区 → **先取 MaxMind**（分区数据更完整，带 zh-CN 翻译时优先取中文；xdb 对
    这些地方只给英文名、粒度也更粗，`1.1.1.1` → `Queensland` / `Brisbane`）
  - 两边**互为兜底**：先取的那边是占位值（`0` / 空）就落到另一边
- **运营商只有 ip2region 能给**（MaxMind 的运营商数据在单独的付费库里）。
- **只装 ip2region 时**，国家字段按 xdb 记录里的 **ISO 国家码**判断（中国是 `CN`）。
  不能按「有没有省市」判断 —— 国外记录同样带省市，1.1.1.1 在 xdb 里是
  `Australia|Queensland|Brisbane|0|AU`，按「有省市就算中国」会把它标成 `CN`，
  「只放行中国」的白名单就形同虚设，而且界面上显示的国家名还是「中国」，看不出异常。
